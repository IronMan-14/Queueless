## Important boundaries

- Native serialization, annotations, custom JSP tags, inter-thread communication and deadlock are explicitly named. They are not optional omissions merely because ordinary application frameworks can hide them.
- `finalize()` receives an accurate legacy explanation. Production cleanup must not depend on finalization or forced garbage collection. A literal legacy example, if an evaluator later requires one, belongs outside the deployed application and cannot promise finalizer execution.
- The source does not demand raw `wait()`/`notify()`, custom annotations, a custom abstract hierarchy, Java Stream API pipelines, or a `Queue` collection. Use such techniques only when justified; Java I/O streams and Stream API pipelines are different concepts.
- Native deserialization is restricted to a small application-owned local preference format with an allowlist, size/graph limits, version checks and field validation. No passwords, sessions, authoritative records, arbitrary imported files or remotely received objects belong in it.
- JSPs contain presentation, not JDBC calls or business decisions. The indicative JSP/JDBC exercises do not require SQL inside JSP templates.
- Roles are authorization data. `User -> Staff -> Admin` is not an appropriate inheritance model merely to demonstrate inheritance.
- Security, idempotency, transactions, unique constraints, tests, HTTPS and operational recovery are engineering requirements of QueueLess. They must not be presented as verbatim syllabus requirements.
